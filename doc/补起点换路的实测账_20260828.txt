补起点换路的实测账 (2026-08-28)
================================

这是 Re2Set_fll_t"补起点"那条路从【三条并存】收成【一条】那次换路的原始报表。
结论写在 hgmLibre2/re2set_fll.go 头注"老账"那一节, 这里放的是数字本身。

三条路各是什么
--------------
  A  = Re2Set_fll_t + MatchScanMode_spanFast : 反向机【只种 accept】(RegexpReverse.ResolveSpanWithin)
                                               回推一个起点, 再正向锚定取最长右端。两趟, 回看窗口【相交】,
                                               给的是"第三种口径"(既不是 leftmost-first 也不是 leftmost-longest)。
  B  = Re2Set_fll_t 默认档                    : 从 max(游标, e-maxL) 起做一次正向【非锚定】longest 搜索。
                                               一趟, 口径严, 贵在【没有上界的条要走完空隙】。
  D2 = Re2Set_fll_t2                          : 反向机【种全部状态】(RegexpSetReverse.GetViableStarts) 收下
                                               [游标, e) 里全部可行前缀起点(降序), 再【升序】逐个正向锚定验,
                                               第一个成的就是答案。口径严, 回看窗口两两【不交】。

  三者共有的定长捷径: minL == maxL ⟹ start = e - minL, 一句减法, 不进正则引擎。

留下来的是 D2, 现在它就是 Re2Set_fll_t 唯一那条路; A / B / MatchScanMode_spanFast / Re2Set_fll_t2
这个类型 全部删除。

口径 (逐区间对拍, 基准取 D2)
-----------------------------
  语料 11 份 × 生产真门表 9 张 = 99 格。每格三条路各扫一遍全文, 把区间按 (条, Lo, Hi) 排成
  规范序再逐处比 —— 🔴 【不能】按吐出来的先后流式比: 对外那三条保证只管到"同一条 pattern 的
  区间按 Lo 升序", 跨 pattern 的先后是没有保证的, 照吐出顺序直接比量到的是"排列不同"。

  D2 vs B    对账 1.619 亿处区间, 差 【0 处】。两条都自称严格 leftmost-longest, 这是
             "敢把默认档换掉"的全部凭据。
  D2 vs A    差 【37 处】, 全在 sbMixed 那份 (产品源码 + 中英文说明书 + 端点 ELF) 上,
             而且每一处都是【A 把左端截短了】:
                 A  [11557133,11557147) "1985-1234567-1"
                 D2 [11557129,11557147) "784-1985-1234567-1"     ← 阿联酋身份证, A 少盖 4 字节
                 A  [8920781,8920786)   "<SYS>"
                 D2 [8920780,8920787)   "<<SYS>>"                ← 提示注入标记, A 两头各少 1 字节
             🔴 这正是"区间偏了 ⟹ 拿去过校验位 (mod-10 / Luhn / mod-97) 会失败 ⟹ 整条真命中
                被下游自己毙掉 = 无声漏报"那一类伤。换路不只是省钱, 是真的修掉了 37 处错边界。

价钱 · 内存
-----------
  11 条门链合计, D2 【每一条都是最快的】: 相对 A 0.48~0.91x, 相对 B 视语料 0.6~1.0x。
  "试/看" (Tries/Walks = 每次回看正向锚定验了几次) 在 99 格里【全是 1.00】—— 升序第一个候选
  就是答案。人造反例 a|[ab]+c 那种 2.00 的退化 (见 TestMatchScanPerfHard) 在真表上不发生。
  常驻: D2 要"反向单条 set"(vp1), A 要"反向单条"(rev1), 同一量级 —— 最大那张 158 条表上
  89 条被真问到位置, vp1 9.6MB vs rev1 7.6MB (1.26x)。相对 B 是【净增】(B 一条反向都不建),
  这一笔是换路的全部代价, 量它用 (*RegexpSet).GetViableOneStats()。

量具
----
  这些报表出自调用方产品的扫描基准包 tests/scanBench: 价钱量具 + 对拍量具
  加三家的入口。两份量具在换路【之后】随 A/B 一起删了 —— 三条路合成一条就没有了对手。
  留下来的是同一批语料同一批门表的单路尺子, 它继续盯"试/看"那一列。

  三条路必须共用【同一个 *RegexpSet】: 同一批 pattern 建三次, 三个 DFA 的状态区落在不同地址上,
  cache set 冲突不一样 —— 实测同一段代码只因为换了个 set 对象就能差 5~8%, 比要量的还大。
