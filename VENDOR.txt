hgmLibre2 — vendored RE2 source
========================================
来源 : https://github.com/google/re2  tag 2023-03-01 (abseil 之前最后一版(社区常用的避开 Abseil 版本), 纯 C++11, 自包含 util/)
许可 : BSD-3-Clause, 见 RE2_LICENSE.txt
取法 : git archive 2023-03-01 (一次性 vendor, 编译期不再下载远程源)

布局
----
re2_*.cc / util_*.cc   : RE2 的 .cc (re2/*.cc + util/{rune,strutil}.cc), 拍平到本目录
                         (cgo 只编 package 目录下的 .cc, 不递归子目录, 故拍平).
                         已剔除: testing/ fuzzing/ util/pcre.* util/benchmark.* util/fuzz.cc util/test.*
internal_include/re2/  : re2/*.h
internal_include/util/ : util/*.h (logging/mutex/strutil/utf/util/flags/mix/malloc_counter)
cre2.h / cre2.cpp      : 我们自己写的极小 C 包装 (不算改 RE2)
cre2_dfastats.cpp      : 进程级 DFA 计数的 hook 安装 (挂 re2::hooks)
internal_include/re2/dfa_stats.h : 本库追加的观测结构体 (ScanStats / MemInfo / AttribInfo)
*.go                   : cgo Go API (Compile/MustCompile + Find/Replace 系列 + RegexpSet 及其观测)

🔴 已改动的上游文件 (升级 RE2 时【不能直接覆盖】, 必须重新打这些改动)
--------------------------------------------------------------------
re2_dfa.cc             : ①转移表槽位 8 字节 State* → 4 字节 arena 下标, 状态从整块 arena 切,
                           arena 按需翻倍 (默认开; -DRE2_DFA_NEXT_BITS=64 -DRE2_DFA_ARENA=0 回到原版)
                         ②per-Set / per-scan 计数 (flush 次数 / 新建状态数 / 额度水位)
                         ③编译期开关后面的排障采集 (RE2_DFA_ATTRIB / TRACE / HOTSTATS, 默认全关)
internal_include/re2/prog.h : 追加 SearchDFA 的可选出参 + GetDFAMemInfo / GetDFAAttribInfo 声明
internal_include/re2/set.h  : 追加 Match 的可选出参 + MemInfo / AttribInfo 声明
re2_set.cc             : 上面那两个声明的实现 (转发给 Prog)
除上面五个文件外, 其余 re2_*.cc / util_*.cc / 头文件本库未再改动。
改动的语义保证: 命中集与原版(-DRE2_DFA_NEXT_BITS=64 -DRE2_DFA_ARENA=0 编出来的那份)逐位一致,
按 pattern 表 × 语料 × 预算的矩阵对拍钉死。

升级 RE2 版本
-------------
重新 git archive 新 tag, 覆盖 re2_*.cc / util_*.cc / internal_include/**. 注意 2023-03 起 RE2 依赖
abseil, 那之后不能再这样直接 cgo (会缺 absl/*), 要回到 cmake 方案. 故本方案钉死在 2023-03-01.
🔴 覆盖前先把上面"已改动的上游文件"那五个的 diff 存下来, 覆盖后重新打上去。
   漏掉头文件 (prog.h/set.h/dfa_stats.h) 会编译报错, 看得见; 但只漏掉 re2_dfa.cc 的话
   【一样编得过】—— 槽位悄悄退回 8 字节指针, 同预算装下的状态数掉回 1/1.74, 原本 0 flush
   的档可能开始 thrash, 除了变慢没有任何症状。所以升级后务必按 README 的方法重新量一遍
   0-flush 门槛。
